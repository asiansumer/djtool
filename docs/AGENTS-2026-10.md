# DJTOOL 协作约定

## 当前依据

- 用户已接受 PRD 的音乐收集、分类、Set 编排与 Serato 单向同步目标。
- **2026-09-23 用户更改分工：助手负责实现和推进，用户负责试用、调试反馈与产品感觉；项目稳定后再集中解释原理。** 这替代此前逐函数教学模式，不再留练习骨架等待用户填写。
- 用户选择第一张浅色双栏方案作为开发起点，允许随着真实功能调整布局。视觉参考在 `design/library-reference.png`，不要求逐像素固定布局。
- 用户要求精美、简洁、清晰、舒适；围绕整理音乐和编排 Set 减少重复操作，不增加装饰性仪表盘。
- 第二轮用户要求直接实现链接收歌、完整元数据，并提升配色；当前调整为石墨灰与柔和白色。SoundCloud 不使用作者描述里的外部下载链接。

## 开发方式

- 自主完成一个能实际试用的功能单元，包含必要的错误处理和验证；不把按钮、模拟数据或接口调查冒充功能接入。
- 保留清楚的中文注释，说明数据流、边界和取舍。解释不阻塞开发，也不把代码生成等同于用户已掌握。
- 当前使用 Python 3.13 + PySide6 + SQLite；技术栈可随实测调整，不为语言名称本身重写。
- 界面、曲库保存、音频读取、后台任务各自承担明确职责。使用项目 `.venv`，不更改全局 Python 环境。
- 在里程碑更新 README / PROGRESS / DEVELOPMENT；PRD 保存产品需求，RESEARCH 保存外部实验依据。

## 数据与验收边界

- 导入复制到用户选择的新曲库，保留源文件；旧曲库不迁移、不删除。
- 同一播放文件可被多个分组或 Set 引用；分类、改显示标题、排序不改变播放路径。
- 去重按文件内容或经过验证的平台歌曲 ID，不按歌名合并 remix 等不同版本。
- 网易云列表读取、完整音频获取分别验收；NCM 格式判断与转码分别验收。
- Serato 接入先使用隔离测试库，确认备份恢复和写入范围；未验证时不写用户真实 Serato 曲库。
- **2026-10-23 用户要求收进来的歌曲自动加入 Serato。** 下载/导入完成后保留待整理，同时补同步到独立的 DJTOOL / 收歌；不要求先整理或加入 Set。Serato 运行时排队，关闭后由 DJTOOL 自动提交，下次启动原生接收；以当前安装的隔离验收为前提，仅维护托管 Crate，不直接写 Serato SQLite、不改音频和用户 Set。准备完成与原生已接收须分别核对和显示。
- **2026-09-26 用户取消 App 的 BPM 功能，识别交给 Serato。** 不恢复自动分析、BPM 筛选或校正控件；只保留原文件标签与历史数据库值，不将旧估计当作当前结果。
- **2026-10-04 用户新增读取 Serato 已有 BPM 并在 DJTOOL 查看，方便排歌。** 允许手动只读同步与曲库、Set、详情显示，不恢复 App 自行计算、BPM 筛选或校正。只缓存经过播放路径、文件大小和状态核对的 Serato 数据；不得覆盖原标签、历史字段、音频、Serato 数据库或表演标记。来源标为 Serato，不把每个已有数值宣称为本次新分析；未知版本和异常保留上次缓存。
- 账号会话保存在 macOS 钥匙串；不得写入代码、SQLite、日志或聊天。网易云有会员是用户已确认的信息，具体歌曲的完整访问仍需实测。
- 重点验证去重、顺序、独立成员关系、失败事务与文件副作用；实际 UI 还需检查拖拽、播放、持久化与空状态。
- 测试音频、UI 模拟和原生窗口检查分别记录。用合成静音完成解码检查，不等于用户真实音频的听感验收。
